## 2026-05-18 - [SQLite Batch Insert Optimization]
**Learning:** Python's `sqlite3` driver sets `cur.lastrowid` to `None` after `executemany()`. The codebase requires retrieving auto-incremented IDs for batch inserts. Calling `SELECT last_insert_rowid()` immediately after `executemany()` safely returns the last auto-incremented ID of the main table, even with AFTER INSERT triggers on main tables (like `msg_fts_insert` moving data to `messages_fts`). We can then calculate the preceding inserted IDs backward using the batch length. Additionally, batch inserts require unique timestamps per row to satisfy regression constraints; using a minor offset like `time.time() + (i * 1e-6)` prevents test failures.
**Action:** When replacing loops of `execute` with `executemany` for batch inserts, always retrieve IDs using `SELECT last_insert_rowid()` post-insert and calculate backwards. Ensure unique constraint requirements (like timestamps) are manually offset in the batched parameter generation.
