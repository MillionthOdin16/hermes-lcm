## 2026-03-10 - Python CPython string .lower() in hot loops
**Learning:** CPython generates a new string object every time `.lower()` is called, even if the string is already lowercase. When performing search ranking inside hot loops (like in `dag.py` and `store.py` where thousands of candidate nodes or messages are processed), redundantly calling `.lower()` on the same candidate strings and search terms for every iteration creates severe memory allocation overhead and a major CPU bottleneck.
**Action:** Always pre-process text invariants (lowercase both the candidate text and the search terms) outside of hot loops. When using shared utility functions (like `count_term_matches`), add an optional flag (e.g., `pre_lowered: bool = False`) to bypass the redundant `.lower()` calls while maintaining backwards compatibility for other callers.
