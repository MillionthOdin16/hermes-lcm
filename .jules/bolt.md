## 2026-10-27 - SQLite executemany() auto-increment ID retrieval
**Learning:** Python's `sqlite3` driver resets `cur.lastrowid` to `None` after calling `executemany()`. To retrieve auto-incremented IDs for batch inserts (when a `RETURNING` clause is not viable), we must execute `SELECT last_insert_rowid()` immediately after the batch insert on the same connection. Since SQLite triggers on the main table (like the ones updating `messages_fts` in `store.py`) do not alter the main table's last insert row id, this safely returns the ID of the last row inserted from the batch. We can then compute preceding IDs backward by subtracting the batch size `last_id - len(params) + 1`.
**Action:** When converting multiple `execute` statements to `executemany` for performance, always use `SELECT last_insert_rowid()` right after `executemany` in the same transaction to reliably fetch the auto-incremented ID, and compute the block of IDs using the batch size.
