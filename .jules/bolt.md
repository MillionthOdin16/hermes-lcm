## 2026-05-18 - Pre-process string invariants outside hot search loops
**Learning:** Repetitive string operations (like `.lower()`) and function calls inside hot loops (e.g., search/ranking loops in `dag.py`, `store.py`, `search_query.py`) create severe CPU bottlenecks, especially in fallback paths scanning many rows. Using list comprehensions with `sum()` and in-line `if/else` can unintentionally lead to evaluating expensive functions twice per item if used naively (e.g., `min(count(...), 1) if ... else count(...)`).
**Action:** Always pre-process invariants (lowercase candidate text and search terms) outside the inner loops. Pass an explicit flag (`is_pre_lowered`) to utility functions to bypass their internal normalizations when pre-computed data is available. Compute matches exactly once per term and accumulate scores explicitly.
