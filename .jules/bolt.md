## 2026-05-18 - [SQLite Batch Insert Optimization and ID Retrieval]
**Learning:** In python's `sqlite3`, using a `for` loop to execute sequential `INSERT` queries is very slow. Replacing this with `executemany` yields a massive performance improvement (e.g., 10x faster for large batches). Furthermore, since `sqlite3` sets `cur.lastrowid` to `None` after `executemany()`, and `RETURNING` clauses might not be supported universally or neatly with `executemany`, you can fetch the inserted IDs by executing `SELECT last_insert_rowid()` right after `executemany()`. This returns the ID of the *last* inserted row. By subtracting the size of the batch, you can correctly calculate all inserted IDs sequentially. Also, when inserting multiple messages, ensure that strict timestamp uniqueness is enforced by applying a tiny offset `(i * 1e-6)` to each row's timestamp.
**Action:** When performing batch inserts into SQLite tables, always use `executemany`. Calculate the resulting `last_insert_rowid()` minus the batch length to derive the autoincremented IDs. Use tiny offsets on timestamps to satisfy uniqueness constraints per row.
