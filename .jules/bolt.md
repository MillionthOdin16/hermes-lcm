## 2026-08-23 - [Batch Insert ID Retrieval and Timestamp Uniqueness in SQLite]
**Learning:** When using `executemany()` with Python's `sqlite3` module to optimize batch inserts, the driver sets `cur.lastrowid` to `None`. To retrieve the auto-incremented IDs for the batch without using a `RETURNING` clause (which requires newer SQLite versions or careful driver support), you can execute `SELECT last_insert_rowid()` immediately after the batch insert to fetch the final ID, and then mathematically compute the preceding assigned IDs backward using the batch length. Additionally, when regressions require strictly unique timestamps per row, applying a minor offset (`time.time() + i * 1e-6`) during batch parameter generation solves the issue cleanly without significantly altering semantic timing.
**Action:** Use this `executemany` offset + mathematical ID calculation pattern for bulk SQLite inserts where IDs must be returned but `RETURNING` cannot be reliably used.
