## 2026-09-04 - [Optimize SQLite Batch Inserts]
**Learning:** Python's `sqlite3` driver resets `cur.lastrowid` to `None` when executing `executemany()`. To retrieve inserted row IDs in a batch without `RETURNING` (which older SQLite versions might lack or have issues with in `executemany`), we can issue a `SELECT last_insert_rowid()` immediately after the `executemany()` call. Triggers on the main table (like `msg_fts_insert`) execute but do not clobber this value on the connection. The preceding IDs can then be inferred by working backwards from this `last_id` using the rowcount. Also, `test_append_batch_timestamps_are_unique_per_row` enforces strictly unique timestamps for each batch entry, requiring an artificial microsecond offset to be injected when constructing batch records in memory.
**Action:** Use `executemany()` with pre-computed arrays including artificial microsecond offsets `time.time() + (i * 1e-6)`. Follow it with `SELECT last_insert_rowid()` to retrieve IDs quickly.
