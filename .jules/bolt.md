## 2026-02-12 - Repetitive String Allocation Anti-Pattern in Fallback Scans
**Learning:** Repetitive string allocations (e.g., calling `.lower()`) inside inner scoring loops for text search processing (like `compute_directness_score`, `dag.py` fallback search, and `store.py` fallback scan) cause significant overhead. In the case of `count_term_matches`, doing `.lower()` inside the utility function meant that for `N` search terms and `M` fallback rows or score iterations, we were generating new strings `O(N*M)` times. However, we cannot simply inline these utilities because doing so will likely violate code reusability rules or PR standards.
**Action:** Always pre-process invariants (e.g., `.lower()` on search terms and candidate strings) *outside* the hot loops. For shared utilities like `count_term_matches()`, add a keyword-only parameter (e.g., `is_lowered=True`) so that calling contexts that already pre-lowered the strings can pass them directly and bypass the allocation inside the utility.
