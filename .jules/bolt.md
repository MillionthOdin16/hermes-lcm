## 2026-08-05 - [SQLite Batch Insert Optimization]
**Learning:** Python's `sqlite3` driver sets `cur.lastrowid` to `None` after `executemany()`. To return the auto-incremented IDs for a batch insert, you can execute `SELECT last_insert_rowid()` immediately afterward to get the ID of the last row inserted in the batch. You can then calculate the preceding IDs backwards based on the length of the inserted batch. Additionally, when using `executemany` for batch inserting rows like messages where a strictly unique timestamp per row is enforced (e.g., to pass regression constraints like `test_append_batch_timestamps_are_unique_per_row`), you must artificially add a minor offset (e.g., `time.time() + (i * 1e-6)`) during batch parameter generation.
**Action:** When converting multiple `execute()` loop inserts into `executemany()` for performance, apply the backward calculation for returned IDs, and add a deterministic tiny increment for timestamps if strictly unique timestamp constraints apply.
