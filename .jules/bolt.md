## 2026-05-18 - SQLite Batch Insert Optimization Pattern
**Learning:** Python's `sqlite3` driver sets `cur.lastrowid` to `None` after `executemany()`. The `executemany` method is significantly faster for batch operations, but when auto-incremented IDs are required, special handling is needed. Because `AFTER INSERT` triggers on main tables (like `msg_fts_insert` in this codebase) do not interfere with the connection's `last_insert_rowid()` result, calling `SELECT last_insert_rowid()` immediately after `executemany()` safely returns the last auto-incremented ID of the main table.
**Action:** Replace looped `execute()` calls with `executemany()` for batch inserts. To recover the inserted IDs without a `RETURNING` clause (which may not be supported or convenient), execute `SELECT last_insert_rowid()` right after `executemany()`, then calculate the preceding IDs backward using `cur.rowcount`. Also, ensure timestamps are strictly unique per row by applying a minor offset (`time.time() + (i * 1e-6)`) during batch parameter generation, as enforced by codebase regression tests.
