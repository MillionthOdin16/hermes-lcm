## 2026-10-14 - Precomputing Invariants in SQLite Result Iteration Loops
**Learning:** Repetitive string operations (like `.lower()`) and function calls inside hot loops (e.g., search/ranking loops in `dag.py`, `store.py`, `search_query.py`) create severe CPU bottlenecks. When scanning thousands of candidate rows, doing `row_content.lower().count(term.lower())` means `term.lower()` is evaluated N times where N is the number of rows scanned, which can be thousands.
**Action:** Always pre-process loop invariants (like `[t.lower() for t in terms]`) outside the iteration block. Similarly, if `content.lower()` is required for multiple calculations, precalculate it once per row at the top of the loop and propagate it using optional parameters to underlying scoring functions like `count_term_matches(lowered_content, lowered_term, is_lower=True)` and `compute_directness_score`.
