## 2026-08-12 - [SQLite executemany & last_insert_rowid pattern]
**Learning:** Python's `sqlite3` driver sets `cur.lastrowid` to `None` after `executemany()`. For batch inserts, doing a single `executemany` followed by `SELECT last_insert_rowid()` returns the last ID. Since IDs are auto-incremented sequentially during the batch, you can infer the entire batch's IDs by calculating backward using `last_id - len(params) + 1`. Also, some tests strictly require unique timestamps per row, which can be achieved in a batch by adding a tiny offset (e.g., `base_ts + (i * 1e-6)`) to each row.
**Action:** Use this pattern whenever batch inserting data that requires returning the auto-incremented IDs to drastically improve insertion performance compared to looping over `execute`. Ensure artificial timestamp distinctness if tests or logic expect strictly distinct times per row.
