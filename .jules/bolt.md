## 2026-08-26 - SQLite Executemany Optimization and Test Constraints
**Learning:** Python's SQLite driver `executemany` method is significantly faster for batch inserts, but it sets `cur.lastrowid` to `None`. To retrieve auto-incremented IDs without `RETURNING` (which is often problematic or unavailable), executing `SELECT last_insert_rowid()` immediately after the `executemany` safely returns the last auto-incremented ID of the main table even when there are `AFTER INSERT` triggers. The previous inserted IDs can then be inferred by working backwards using the length of the batch. Also, when switching from single inserts to batch array inputs in the `store.py`'s `append_batch`, the code must artificially offset the generated timestamp for each row in the array (e.g. `time.time() + (i * 1e-6)`) in order to satisfy the unique timestamp constraint checked by `test_append_batch_timestamps_are_unique_per_row`.
**Action:** When optimizing batch inserts with `executemany`, use `SELECT last_insert_rowid()` to retrieve inserted IDs, and strictly account for unique constraint expectations (like unique timestamps) when pre-computing the batch parameters instead of relying on the per-iteration delays that existed in the slower loop.
