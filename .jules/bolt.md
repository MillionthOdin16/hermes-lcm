## 2026-08-18 - SQLite Batch Insert Optimization
**Learning:** Python's `sqlite3` driver resets `cur.lastrowid` to `None` when executing `executemany()`. To get auto-incremented IDs for batch inserts without requiring a SQLite version that supports the `RETURNING` clause, you must run `SELECT last_insert_rowid()` immediately after `executemany` (in the same lock/transaction) to fetch the final ID, and then subtract the batch size to determine the range of inserted IDs. Additionally, in `store.py`, a small time offset per row prevents strictly identical timestamps and failing regression tests (`test_append_batch`).
**Action:** Use `executemany` with this workaround for bulk message insertions in SQLite to drastically improve performance (10x faster) over repeated single-row `execute` calls.
