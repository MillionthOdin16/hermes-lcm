## 2026-10-24 - SQLite Batch Insert Last Row ID Pitfall & RETURNING Optimization
**Learning:** Python's `sqlite3` driver sets `cur.lastrowid` to `None` after `executemany()`. While it is tempting to use `SELECT last_insert_rowid()` immediately after `executemany` and subtract `len(batch)` to determine the IDs inserted, this is unsafe. It assumes contiguous ID generation, which can fail if `AUTOINCREMENT` is not strictly enforced, if IDs are reused, or if the max ROWID is reached. The safest and most performant pattern for retrieving IDs during a batch insert in SQLite is using a dynamically constructed `INSERT INTO ... VALUES (...), (...) RETURNING id` query. However, SQLite limits the maximum number of query parameters (default 999). Therefore, chunk the batch insertions such that `chunk_size * parameters_per_row <= 999` (e.g., 71 rows for 14 columns).
**Action:** Always prefer `INSERT INTO ... RETURNING` dynamically chunked within SQLite limits for bulk inserts instead of `executemany` when you need to safely retrieve the generated primary keys.
