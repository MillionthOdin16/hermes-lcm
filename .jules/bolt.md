## 2026-09-07 - [Optimize store message appends with executemany]
**Learning:** Python's `sqlite3` driver resets `cur.lastrowid` to `None` after `executemany()` calls. To fetch auto-incremented IDs for batch insertions safely, use `SELECT last_insert_rowid()` immediately after insertion and calculate the preceding IDs backwards based on the batch length. Also, SQLite requires manually shifting generated batch timestamps by a micro-offset (e.g. `base_time + (i * 1e-6)`) to preserve chronological distinction and satisfy regression tests enforcing strict timestamp uniqueness per row.
**Action:** When migrating single insert loops to `executemany` for batch processing in SQLite, remember to offset row timestamps to enforce uniqueness and use `last_insert_rowid()` with a backwards calculation to infer row IDs securely.
