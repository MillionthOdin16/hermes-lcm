## 2026-03-24 - [Optimize SQLite batch insert]
**Learning:** Python's sqlite3 executemany does not return the list of inserted rowids immediately, but when performing batch inserts (like in `append_batch`), substituting a loop of `.execute()` with a single `.executemany()` drastically improves performance by reducing Python-to-C overhead. SQLite provides a fast path to obtain the last inserted rowid even with triggers (like `msg_fts_insert` in `store.py`) firing AFTER INSERT on the main table. The last insert rowid can be fetched via `SELECT last_insert_rowid()`, and then we can calculate the previous rowids backwards because SQLite auto-increments sequentially in an `executemany` without gaps. However, for `hermes-lcm`'s message store, there's a strict testing constraint that batch append timestamps must be uniquely increasing per row (`test_append_batch_timestamps_are_unique_per_row`). Therefore, generating the params using Python with `time.time() + (i * 1e-6)` is required before `executemany`.
**Action:** Use `executemany()` for `append_batch` rather than a loop of `execute()` to eliminate Python-level SQLite overhead. Ensure timestamps are strictly increasing per row using `time.time() + (i * 1e-6)` to satisfy constraints. Calculate inserted IDs mathematically from `last_insert_rowid()` if `executemany()` does not return all IDs directly, since SQLite IDs increment sequentially within a single transaction.
